# CRO Rules — Viatours Voyage

The site should convert qualified visitors without using manipulative patterns.

## Core principle

Every important page should answer:

1. What is this?
2. Why should I care?
3. Why should I trust it?
4. What can I do next?

## CTA hierarchy

- Give each section a clear primary action when an action is expected.
- Use specific CTA language such as “Explore tours”, “View details”, or “Plan your trip” when appropriate.
- Avoid competing primary CTAs with equal visual weight.
- Place CTAs near the decision point, not only at the bottom of a page.

## Reduce friction

Watch for:

- unclear pricing;
- hidden booking requirements;
- long forms;
- unnecessary steps;
- weak mobile controls;
- slow image-heavy sections;
- missing trust information;
- ambiguous buttons;
- dead-end pages.

## Trust

Use relevant proof such as:

- transparent policies;
- clear contact/support information;
- authentic reviews;
- secure payment information;
- destination/tour details;
- useful FAQs.

Do not fabricate reviews, scarcity, ratings, statistics, or guarantees.

## Measurement-ready design

Important interactions should have stable identifiers or semantic labels so analytics can be added later without redesigning the UI.

Examples:

- primary CTA;
- search submit;
- tour-card click;
- filter change;
- booking start;
- checkout start;
- login/signup completion.

## CRO quality gate

A visually impressive section is not automatically a good section. Before shipping, verify clarity, friction, trust, CTA hierarchy, mobile usability, and measurable user intent.
